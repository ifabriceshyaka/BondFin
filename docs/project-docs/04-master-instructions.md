# BondFin Collective — Master Instructions

## Working Method
Before making changes:
1. Explain what was found
2. Explain why it matters
3. Explain the proposed solution
4. List the files that would change
5. Explain expected behavior
6. Explain how it will be tested
7. Ask for confirmation when changes affect schemas, RLS, admin roles, payouts, or major UI design

## Safe Local Fixes
- explain
- implement
- run npm run lint
- run npm run build
- run tests
- report results
- review diff

## Response Format
For each improvement, use:
- Finding
- Reason
- Proposed Solution
- Files Affected
- Expected Behavior
- Verification

## Scope Rules
- No feature creep
- No redesign scope
- No platform complexity
- No unapproved database changes
- No security weakening
